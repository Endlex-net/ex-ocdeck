## Why

Git 评审页是任务改动的核心查看入口，但当前 diff 浏览体验存在五个明确卡点：并排 diff 横向滚动不协同、文件列表只能看到路径尾部、文件分组割裂且状态不直观、缺少 tree 形态、以及无法查看迭代分支相对基础分支的已提交差异（既有 spec 明确将该能力留待后续迭代）。这些缺口迫使用户回到本地工具完成评审，削弱了 Web 端评审闭环。

## What Changes

- **并排 diff 横向滚动协同**：side-by-side（不换行）形态下，拖动任一侧的横向滚动，另一侧同步移动。
- **diff 文件列表横向滚动**：文件列表行支持左右拖动查看完整路径，不再只能看到路径尾部。
- **文件列表混合展示**：已暂存 / 未暂存 / 未跟踪文件混合在同一列表展示，通过文件名颜色区分三种状态（替代当前硬编码三分组）；同一文件同时有暂存与未暂存变更时的呈现方式在 specs 阶段确定。
- **文件列表 tree 模式**：文件列表支持树形展示形态。
- **文件列表可读性**：flat 形态条目先展示文件名、再展示目录路径；tree 形态文件节点仅展示文件名（目录层级由树结构表达）；状态颜色语义按修改观感校准（已暂存成功绿 / 未暂存 teal / 未跟踪琥珀）。
- **迭代分支 vs 基础分支 diff**：新增分支对比视图，展示迭代分支相对基础分支（three-dot 语义，即仅迭代分支引入的变更）的已提交差异，并**混合展示当前未提交变更**（未提交条目在分支视图中可编辑/批注/提交，等同于对已提交文件的新修改）；基础分支默认取任务的 `base_ref`，可手改为其他 ref；该视图与现有未提交变更视图并存。
- **扩展点预留**：设计为未来「任意文件只读浏览」能力预留扩展点（不实现）。

**非目标（明确不做）**：commit 历史 / 单 commit diff 视图、冲突解决 UI、文件列表搜索过滤、rename 旧→新路径显示、视图偏好持久化（形态/换行）、two-dot 对比、任意文件阅读能力（仅预留扩展点）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `git-operations`：diff 视图渲染新增并排横向滚动协同行为；diff 文件列表展示形态变更（混合展示 + 状态颜色 + 横向滚动 + tree 模式）；新增迭代分支 vs 基础分支的已提交差异查看能力（解除既有「分支变更视图留待后续迭代」的限制）；「repo 项目 local-path 模式任务的 git 能力」中 diff 来源范围相应扩展。

## Impact

- **前端**：`web/src/components/GitPanel.tsx`（文件列表重构）、`web/src/components/diff/DiffViewer.tsx`（滚动协同）、`web/src/legacy-components.css`（列表与滚动样式）、`web/src/api.ts` / `web/src/types.ts`（分支 diff API 契约）。
- **后端**：`internal/api/git.go`、`internal/task/gitops.go`、`internal/infrastructure/git/`（分支 diff 相关端点与 git 原语扩展）。
- **API**：新增或扩展任务级 git diff 相关 HTTP 契约（请求参数与响应形态在 specs 阶段确定）。
- **依赖**：无新增第三方依赖的预期。
- **既有行为保护**：未提交三组 diff 来源语义、diff 内容读取安全约束（路径防御/有界读取/二进制嗅探）、批注与编辑能力的行为契约 MUST NOT 被破坏；`dir` 项目任务的 git 降级规则不变。
