# Delta Spec: diff-annotations

本 spec 为新增 capability，定义 git diff 页面上的批注、整体提交给 task agent 会话修复、以及提交历史的行为契约。本 capability 仅在 git 面板可用的任务上生效（`kind=dir` 项目任务的 git 面板降级规则见 `git-operations`，批注能力随之整体不可用）。

## ADDED Requirements

### Requirement: 批注的特殊文件边界
批注 SHALL 仅对渲染了 merge 视图的文件内容可用：binary 文件、gitlink（子模块）变更、双侧均不存在的文件 MUST NOT 提供批注手势。truncated 文件 SHALL 允许对截断范围内的可见文本批注，其快照以实际可见内容为准。untracked 文件 SHALL 允许对新侧批注；已删除文件（新侧不存在）SHALL 允许对旧侧批注。

#### Scenario: binary 文件不可批注
- **WHEN** 用户查看 binary 文件（isBinary=true，未渲染 merge 视图）
- **THEN** 系统不提供批注手势

#### Scenario: 截断文件批注可见范围
- **WHEN** 用户对 truncated 文件截断范围内的可见文本框选批注
- **THEN** 批注正常创建，快照以可见内容为准

#### Scenario: 已删除文件批注旧侧
- **WHEN** 用户对已删除文件（新侧不存在）的旧侧内容批注
- **THEN** 批注正常创建，所在侧记录为旧侧

### Requirement: 批注创建
系统 SHALL 允许用户在 git diff 页面的查看模式下，通过框选代码段落或点击代码行创建批注。每条批注 MUST 记录：文件路径、所在侧（旧侧/新侧）、创建时的 diff 来源元组（ref 与 untracked 标记）、1-based 闭区间行范围、快照窗口首行行号、快照窗口行数、快照窗口全文、用户评论。来源组合 MUST 合法：untracked 批注的 ref 必须为空且侧必须为新侧；非法组合 MUST 在落库前以 invalid_input 拒绝。快照窗口 MUST 为选中段及其前后各 3 行上下文（文件边界处裁短），使接收方能区分文件内重复出现的相同文本。未输入任何评论的批注 MUST NOT 留存（关闭批注输入即丢弃，不产生记录）。

选区 MUST NOT 跨侧：一次批注只能锚定单侧连续行。unified（单列）形态下的归属唯一：新增行与未变上下文行归属新侧、删除行归属旧侧；并排形态按用户指针所在侧归属。快照 MUST 从 diff 接口返回的原始侧内容按行号构造并保留行尾字符，MUST NOT 取自编辑器内部文档态（其换行会被规范化，导致 CRLF 文件批注立即漂移）。

#### Scenario: 框选创建批注
- **WHEN** 用户在查看模式下框选 diff 中的一段代码并输入评论
- **THEN** 系统创建批注，记录文件、侧、来源元组、行范围、快照窗口（选中段+前后各 3 行）与评论

#### Scenario: 点击创建单行批注
- **WHEN** 用户在查看模式下点击某代码行并输入评论
- **THEN** 系统创建锚定该单行的批注

#### Scenario: 空评论不留存
- **WHEN** 用户触发批注输入但未输入任何文字即关闭（Esc 或点击空白）
- **THEN** 系统丢弃该批注，批注列表无新增记录

#### Scenario: 跨侧选区拒绝
- **WHEN** 用户框选范围跨越 diff 两侧（或 unified 形态下跨越归属不同侧的区域）
- **THEN** 系统不创建批注并提示用户改为单侧选择

### Requirement: 批注行内标记
打过批注的代码行 SHALL 在 diff 视图中显示弱存在感标记（如行号旁小圆点）。标记 MUST NOT 遮挡代码内容，MUST NOT 改变 diff 的红绿主色语义。标记与批注的匹配 MUST 以视图身份三元组（文件路径、ref、untracked）为准——同一路径的 staged/unstaged/untracked 视图 MUST NOT 互相显示对方的批注标记。同一行有多条批注时 MUST 聚合为一个带数量的标记；悬停 SHALL 按（创建时间、id）顺序显示各条评论摘要；点击 SHALL 在批注列表中定位并高亮全部匹配批注。单条批注时悬停显示评论摘要、点击定位对应条目。

#### Scenario: 悬停查看批注摘要
- **WHEN** 用户悬停某行的批注标记
- **THEN** 系统显示该条批注的评论摘要

#### Scenario: 标记与列表互定位
- **WHEN** 用户点击某行的批注标记
- **THEN** 批注列表定位并高亮对应批注条目

### Requirement: 批注列表管理
系统 SHALL 提供批注列表面板，展示当前全部活动批注。用户 MUST 可编辑单条批注的评论、删除单条批注。删除操作 MUST NOT 提供撤回。列表 UI SHALL 保持低存在感，不干扰 diff 浏览主流程。

#### Scenario: 编辑批注评论
- **WHEN** 用户在批注列表中修改某条批注的评论
- **THEN** 系统更新该批注，其余字段不变；评论 trim 后为空白时拒绝修改并返回明确错误

#### Scenario: 删除批注无撤回
- **WHEN** 用户在批注列表中删除某条批注
- **THEN** 该批注被移除，系统不提供撤回入口

### Requirement: 批注锚定状态
每条批注 SHALL 具有锚定状态：有效（active）或已漂移（stale）。系统 MUST 按批注持久化的来源元组（ref/untracked/侧）重读该侧当前内容，取快照窗口对应行范围与快照全文比对：不相等即转为已漂移。**截断文件的窗口完整落在返回内容前缀内时 MUST 正常比对并保持有效；仅当窗口无法完整取得（截断点落在窗口内、文件删除、不可读）时才转为已漂移**。任何读取失败 MUST NOT 报错阻断批注列表。已漂移批注 MUST 在列表与行内标记中显示漂移标识；已漂移批注所在行无法在原位置显示标记时，仅在列表中标记。已漂移批注 MUST 仍可被提交，其快照窗口全文作为接收方的定位依据。

#### Scenario: 批注漂移标记
- **WHEN** 批注创建后对应代码被修改，快照窗口与当前内容失配
- **THEN** 该批注转为已漂移并显示漂移标识，仍可正常提交

#### Scenario: 截断文件窗口完整保持有效
- **WHEN** 批注位于 truncated 文件、且其快照窗口完整落在返回内容前缀内且未失配
- **THEN** 该批注保持有效状态，不因 truncated 标记转为已漂移

#### Scenario: 漂移批注提交
- **WHEN** 用户提交包含已漂移批注的批次
- **THEN** 提交内容中以该批注的快照窗口全文作为定位依据，而非仅依赖行号

### Requirement: 批注持久化
活动批注 SHALL 持久化存储。服务重启或页面刷新后，活动批注列表 MUST 完整恢复。批注 MUST 按任务隔离，不同任务的批注互不可见。

#### Scenario: 重启后批注不丢
- **WHEN** 用户创建若干批注后服务重启或页面刷新
- **THEN** 重新打开该任务的 git 面板时全部活动批注完整存在

### Requirement: 提交预览与补充说明
用户触发「提交给 AI」时，系统 SHALL 先展示提交预览：列出将提交的批注条目、提供可折叠的补充说明输入框。用户 MUST 可在预览中临时移除个别条目（本次不提交）。预览中临时移除的条目 MUST 保留在活动批注列表中，MUST NOT 被清空或删除。**提交请求 MUST 携带预览确认时各批注的版本标识；确认后任何批注被修改或删除，提交 MUST 被拒绝（conflict）并提示刷新后重新确认**——投递内容 MUST 与用户确认的内容一致。用户确认后 MUST 才执行提交。

#### Scenario: 预览确认提交
- **WHEN** 用户点击「提交给 AI」，在预览中确认
- **THEN** 系统提交预览中列出的全部条目及补充说明

#### Scenario: 预览中临时移除条目
- **WHEN** 用户在预览中临时移除某条批注后确认提交
- **THEN** 该条目不参与本次提交，且仍保留在活动批注列表中

### Requirement: 提交给 task agent 会话
确认提交后，系统 SHALL 由后端向当前 task 的 agent 会话调用 `prompt_async` 消息发送接口。提交内容 MUST 包含：每条批注的文件与行号（以 `Q(path):start-end` 表述，单行为 `Q(path):start`）、快照窗口全文、评论与用户补充说明；批注涉及的文件 MUST 以 file part（`file://` 绝对路径 URI，mime text/plain）附在文本 part 之后一并提供给 agent。文件在发送时缺失或非普通文件时，系统 MUST 跳过该文件的 file part 且 MUST NOT 阻断发送。提交内容 MUST NOT 包含相关 diff/Context 段（批注快照窗口自带上下文即足够）。提交内容 SHALL 具有体积保护：核心区（固定指令头、补充说明、全部批注块）超过体积阈值时，系统 MUST 拒绝该次提交并返回明确错误，MUST NOT 创建提交记录、MUST NOT 清空批注。提交记录的 truncated 标记恒为 false（不存在 diff 上下文截断，字段仅保留 wire 兼容）。

投递语义 MUST 为至多一次：发送结果不确定（网络错误、超时、进程重启）时，提交 MUST 转为「投递未知」状态并展示给用户，MUST NOT 自动重投。发送前读取提交条目快照失败时，该提交 MUST 转为失败且不产生任何发送副作用。

修复执行者 MUST 始终为当前 task 的 agent 会话。系统 MUST NOT 改经平台 LLM 直连生成修改。目标环境的 agent 会话不具备消息发送能力时，系统 MUST 禁用提交能力或返回明确错误，MUST NOT 改走其他 AI 通道。

#### Scenario: 提交组装内容完整
- **WHEN** 用户确认提交 3 条批注并填写补充说明
- **THEN** 发送给 agent 会话的内容包含每条批注的文件与行号、快照窗口、评论、补充说明，且涉及文件以 file part 附于文本 part 之后

#### Scenario: 提交涉及文件缺失不阻断发送
- **WHEN** 提交中某批注涉及的文件在发送时已不存在于工作区（或非普通文件）
- **THEN** 该文件的 file part 被跳过，提交仍正常发送，批注快照与评论保留在提交内容中

#### Scenario: 核心内容超限拒绝提交
- **WHEN** 核心区（固定指令头、补充说明、全部批注块）超过体积阈值
- **THEN** 提交被拒绝并返回明确错误，不创建提交记录、批注保持原样

#### Scenario: 提交条目快照读取失败
- **WHEN** 发送前读取该提交的条目快照失败（存储异常）
- **THEN** 该提交转为失败并记录明确错误，不调用消息发送接口、不产生任何发送副作用

#### Scenario: 投递结果不确定
- **WHEN** 发送过程中发生网络错误或超时，无法确定 agent 会话是否已收到
- **THEN** 该提交转为「投递未知」状态并展示给用户，系统不自动重投

#### Scenario: agent 会话不支持消息发送
- **WHEN** 目标环境的 agent 会话不具备消息发送能力
- **THEN** 系统禁用提交能力或返回明确错误，不尝试其他 AI 通道

### Requirement: 提交排队与撤回
提交条目 SHALL 先持久化再调度。提交内容以提交时刻的批注快照为准，排队期间用户对活动批注的编辑/删除 MUST NOT 影响已提交内容。agent 会话忙时，提交 MUST 进入该任务的队列按提交顺序等待；agent 空闲后 MUST 按序发送。排队中（未开始发送）的提交 MUST 允许用户撤回；已开始发送或已完成的提交 MUST NOT 可撤回，撤回不保留任何记录。服务重启后，未开始发送的排队提交 MUST 恢复等待；重启时处于发送中的提交 MUST 转为「投递未知」，MUST NOT 自动重投或重复投递。

#### Scenario: busy 排队
- **WHEN** 用户确认提交时 agent 会话正在执行
- **THEN** 提交条目先持久化并进入队列，agent 空闲后按提交顺序发送

#### Scenario: 排队中撤回
- **WHEN** 提交尚在排队（未开始发送）时用户撤回
- **THEN** 该提交被取消且不发送，其中批注保留在活动批注列表，提交历史与队列中均不保留该次记录

#### Scenario: 排队期间编辑批注
- **WHEN** 提交排队期间用户编辑了其中某条批注的评论
- **THEN** 已提交内容保持提交时刻快照不变，活动批注列表中的新版本不受影响

#### Scenario: 重启恢复不重复投递
- **WHEN** 服务在提交排队或发送期间重启
- **THEN** 恢复后排队中的提交继续等待发送；发送中的提交转为「投递未知」；任何提交至多被投递一次

### Requirement: 提交清空与历史
提交成功投递（状态转为 sent）后，系统 SHALL 仅清空本次实际提交且未被再次编辑的批注（排队期间被编辑的批注新版本 MUST 保留），并将该次提交归档为只读历史记录。历史记录 MUST 持久化、只读、可删除，仅包含成功投递的提交，展示提交时间、补充说明与批注快照。失败与投递未知的提交 MUST 在单独的失败分区展示（可删除），MUST NOT 混入历史；撤回的提交 MUST NOT 留下任何记录。

#### Scenario: 提交后清空与归档
- **WHEN** 提交成功投递
- **THEN** 本次提交且未被再次编辑的批注从活动列表清空，该次提交出现为只读历史记录

#### Scenario: 排队期间编辑的批注保留
- **WHEN** 提交排队期间用户编辑了某条批注，随后该提交成功投递
- **THEN** 该批注的新版本保留在活动批注列表，历史记录中为提交时刻快照

#### Scenario: 删除历史记录
- **WHEN** 用户删除某条历史记录
- **THEN** 该记录被移除，不影响其他历史与活动批注
