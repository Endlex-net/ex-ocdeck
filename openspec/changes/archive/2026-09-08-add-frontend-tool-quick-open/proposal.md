# Proposal: add-frontend-tool-quick-open

## Why

用户经常使用 GoLand / VSCode review 代码，当前要为某个任务打开编辑器时，需要先在终端 pwd 获取任务工作目录，再手动用编辑器打开，步骤繁琐。由于服务端可能运行在远程机器上，"在编辑器中打开"必须是纯前端行为（在用户的本机浏览器侧唤起本机编辑器），不能依赖服务端执行命令。

## What Changes

- 设置页新增「常用工具」子标签：提供 VSCode、GoLand 两个工具的启用开关，各自独立开启/关闭，**默认均关闭**；开关状态为纯前端偏好，按设备持久化（localStorage），不写入服务端。
- 任务详情页（任务工作台）页头新增「在编辑器中打开」快捷入口：
  - 仅当至少一个工具开关开启时呈现；两个开关都关闭时入口完全隐藏、无占位。
  - 入口为「工具图标主按钮 + 下拉选择」组合形态（即使只启用一个工具也保持该结构）；点击主按钮直接以当前默认工具打开任务工作目录；下拉中点击某个已启用工具即用它打开，并将其设为默认；下拉菜单以 ✓ 标识当前默认工具，默认选择同样按设备持久化。
  - 打开目标为任务实际工作目录：worktree 模式任务打开其 worktree 目录；dir 项目任务与 repo 项目 local-path 模式任务打开其项目目录（统一取任务接口返回的工作目录字段）。
  - 唤起动作发生在本机浏览器侧，服务端无感知、无新增 API。
- 每个工具支持可选的自定义唤起 URI 模板：默认使用内置本地模板（默认行为不变）；远程开发机等场景由用户自行配置模板实现（如 VSCode Remote-SSH 形式），设置页提供对应能力说明（含各工具对远程打开的支持情况）。

非目标：

- 不新增/修改任何服务端接口与后端逻辑。
- 不支持 Finder、系统终端或其他编辑器等更多工具（工具集固定为 VSCode、GoLand）。
- 不在指挥中心、项目管理页等其他页面提供快捷打开入口（仅任务详情页）。
- 不将「常用工具」子标签加入 ⌘K 命令面板静态入口（与通知子标签一致，保持面板入口收敛）。
- 不内置远程主机/SSH 连接管理：远程打开仅通过自定义唤起 URI 模板由用户自行配置，且仅 VSCode 侧存在可用形式（GoLand 无此能力，在设置页能力说明中明示）。

## Capabilities

### New Capabilities

- `editor-quick-open`: 前端本机编辑器快捷打开能力——设置页「常用工具」子标签的 VSCode/GoLand 启用开关（默认关闭、localStorage 持久化）、可选的自定义唤起 URI 模板（默认内置本地模板），与任务详情页页头的编辑器快捷打开入口（默认工具记忆、按任务工作目录唤起本机编辑器）。

### Modified Capabilities

- `web-ui-shell`: 路由收敛 requirement 变更——设置页深链子标签枚举新增「常用工具」子标签对应值。

## Impact

- **前端代码**：`web/src`（设置页子标签与路由、任务详情页页头、新增前端偏好存储模块与编辑器唤起模块、相关组件与样式）。
- **路由**：`#/configs` 增加「常用工具」子标签的深链支持。
- **后端/API**：无改动、无新增依赖。
- **持久化**：仅浏览器 localStorage（本设备），不涉及服务端存储与迁移。
- **测试**：前端单元/组件测试（偏好存储读写、入口显隐、唤起链接构造）。
