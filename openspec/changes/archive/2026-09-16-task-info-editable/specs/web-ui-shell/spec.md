## ADDED Requirements

### Requirement: 任务设置页任务信息卡片

任务工作台的设置页签 SHALL 提供单卡片「任务信息」区块。展示态下字段连续排列（不区分只读区与编辑区）：项目、状态、基础分支（dir / local-path 任务显示路径替代）、worktree 路径、创建时间、任务名称、分支（gitless 任务 MUST NOT 渲染分支行）。卡片头部 SHALL 提供单一「编辑」按钮；点击进入编辑态：任务名称变为可编辑输入、分支 slug 变为可编辑输入（仅 worktree 模式任务；dir / local-path 任务编辑态不出现分支 slug 输入），其余字段保持只读展示，同时提供「取消」与「保存」。编辑态分支 slug 输入 SHALL 实时展示最终分支名预览（沿用该任务当前分支的原有前缀）。取消 MUST 放弃全部未保存修改回到展示态。

保存语义：任务名称与分支 slug 在同一次保存中提交，相互独立校验——两项均未修改时保存为幂等同值写（成功、无实际变更）；名称非法（trim 后为空）或 slug 非法/冲突时 MUST 展示服务端错误并保持编辑态，已确认的其他项修改 MUST NOT 落账（整次保存原子成功或失败）。保存时若分支 slug 发生变化，MUST 先弹出危险确认（说明旧分支名将废弃、worktree 路径与提交内容不变，复用既有危险确认 modal 模式），用户确认后才发起保存；仅名称变化时无需确认。保存成功回到展示态并展示新值。

#### Scenario: 展示态字段连续排列

- **WHEN** 用户打开任务工作台设置页签
- **THEN** 「任务信息」卡片以展示态连续列出项目、状态、基础分支（或路径）、worktree 路径、创建时间、任务名称、分支，卡片头部有「编辑」按钮

#### Scenario: 进入编辑态修改名称

- **WHEN** 用户点击「编辑」，修改任务名称后点击「保存」（分支 slug 未变）
- **THEN** 无需确认直接保存，成功后回到展示态并展示新名称

#### Scenario: 修改分支 slug 需危险确认

- **WHEN** 用户在编辑态修改分支 slug（预览显示新分支名）并点击「保存」
- **THEN** 弹出危险确认（说明旧分支名将废弃、worktree 路径与提交内容不变），确认后才发起保存；取消确认则留在编辑态

#### Scenario: 保存失败保持编辑态

- **WHEN** 保存因名称为空或 slug 非法/冲突被服务端拒绝
- **THEN** 展示错误信息，保持编辑态与用户输入，任务名称与分支均保持原值

#### Scenario: gitless 任务编辑态无分支输入

- **WHEN** 用户对 dir 项目或 local-path 模式任务点击「编辑」
- **THEN** 编辑态仅任务名称可编辑，不出现分支 slug 输入

#### Scenario: 取消放弃修改

- **WHEN** 用户在编辑态修改了名称或 slug 后点击「取消」
- **THEN** 回到展示态，全部字段展示原值，未发起任何保存请求
