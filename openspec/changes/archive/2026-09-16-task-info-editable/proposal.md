## Why

任务创建后，任务名和 worktree 分支名就完全不可修改：分支名由创建时的 AI slug 一次性生成，前缀 `ocdeck/` 硬编码在代码里。用户在任务执行一段时间后想改名、想用更有意义的分支名、或想用团队约定的前缀，都没有任何入口。

## What Changes

- 支持创建任务后重命名任务名（rename taskname），重命名对已激活任务也立即生效（更新 env 快照与已有会话标题）。
- 支持创建任务时可选指定分支 slug；最终分支名由当前默认前缀与 slug 构成，未指定时继续使用现有 AI 自动生成行为。
- 支持对已创建任务单独修改分支 slug；输入仍为 slug，并沿用该任务当前分支的原有前缀构成新分支名；该操作与任务重命名相互独立，worktree 路径保持不变。
- 支持配置 worktree 分支名的默认前缀（默认值维持 `ocdeck`），仅对之后创建的任务生效，存量任务不受影响。
- Web UI：任务设置页增加单卡片"任务信息"区块，将基础信息与可编辑的任务名称、分支 slug 连续排列展示，通过一个编辑按钮进入该区块的编辑态；任务创建表单在折叠的高级选项中提供可选的分支 slug 输入；全局设置页新增分支前缀配置入口。

### 范围边界与非目标

- 任务重命名与分支改名是两个相互独立的操作，不做联动。
- 不修改 worktree 的磁盘路径，不迁移或重建 worktree。
- 分支改名不改变分支指向的提交内容，只改名字。
- 前缀配置不回溯修改存量任务的分支名。
- 已创建任务的分支改名沿用该任务原有分支前缀；全局前缀配置不影响存量任务的分支改名前缀。
- 无分支（in-place）任务只支持任务重命名，不涉及分支操作。
- 任务名不做唯一性强制（与现状一致）。
- 不改变任务状态机、生命周期钩子与激活流程的既有行为。

## Capabilities

### New Capabilities

- `worktree-branch-prefix`: worktree 分支默认前缀的应用级配置（dataDir JSON 存储、读写 API、设置页入口、仅新任务生效）。`global-config-management` 的 Purpose 限定为 `~/.config/opencode/` 配置文件管理，本配置为应用级设置（与 palette-config 同构），故独立为新 capability。

### Modified Capabilities

- `task-lifecycle`: 新增任务名重命名、创建时指定分支 slug、已创建任务分支改名的任务级行为需求；任务创建的分支命名规则由硬编码前缀改为可配置前缀。
- `git-operations`: 新增本地分支改名这一 Git 操作能力。
- `command-center`: 创建任务表单中分支 slug 的高级选项输入需求。
- `web-ui-shell`: 任务设置页任务信息卡片的展示与编辑需求。

## Impact

- **任务领域与服务接口**：支持任务名称与分支 slug 的更新，并保证已激活任务的名称变化同步到运行时环境快照与已有会话标题。
- **任务创建流程**：支持可选的分支 slug 输入，未指定时行为不变。
- **Git / worktree 基础设施**：新增分支改名能力；分支名生成逻辑读取可配置前缀；既有任务继续按持久化的 worktree 路径操作，修改前缀不得迁移、重建或重算既有 worktree 路径。
- **配置持久化**：保存 worktree 分支默认前缀，并供后续新任务创建使用。
- **Web UI**：任务设置页（任务信息区块）、任务创建表单（高级选项）、全局设置页（前缀配置）三处界面变更。
