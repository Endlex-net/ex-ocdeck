## ADDED Requirements

### Requirement: 任务工作台网页全屏布局与入口

任务工作台 SHALL 允许从当前 TUI、Shell 或 Git 标签进入网页内全屏（Zen）模式。进入后，系统 MUST 隐藏全局侧栏和任务页头，保留工作台标签栏、当前工作区及明确的全屏退出按钮，使当前工作区利用释放的可视空间。ServerStatusBanner MUST 保持既有可见性。标签栏 MUST 提供随当前状态显示 `zen` 或 `out zen` 的固定操作入口；已进入 Zen 后切换到“设置”也保持该退出入口。该模式 MUST NOT 调用浏览器原生 Fullscreen API。退出后 MUST 恢复普通工作台布局，且 MUST NOT 修改用户已有的侧栏折叠状态、侧栏宽度或其他持久化布局偏好。

桌面端（≥768px）Zen SHALL 默认展示独立于全局侧栏的 44px 任务状态窄栏：窄栏仅包含活跃及挂起任务的状态点与当前任务标识，沿用全局侧栏的任务数据、排序、状态及过渡态语义，不包含品牌、全局导航、项目分组标题或侧栏底栏。任务状态 MUST 来自现有共享 projects store，MUST NOT 新增轮询或第二条数据流订阅。窄栏底部 MUST 提供隐藏按钮；隐藏后 MUST 移除整条窄栏及其边框，仅在工作区左下角保留可发现的小型展开按钮，使用户无需退出 Zen 即可恢复窄栏；MUST NOT 保留全高残轨。窄栏显隐在 TUI、Shell、Git、设置标签切换间保持，仅属于当前 Zen 会话；退出 Zen、切换任务、离页或刷新后 MUST 重置为下一次进入 Zen 时默认展示。移动端（≤767px）MUST NOT 展示任务状态窄栏。任务悬浮详情遵循「全局应用壳层与侧栏导航」的统一契约。

#### Scenario: 从 TUI 进入网页全屏

- **WHEN** 用户在任务工作台的 TUI 标签点击 `zen`
- **THEN** 全局侧栏和任务页头隐藏，标签栏、TUI 工作区及 `out zen` 按钮保持可见，浏览器不进入原生全屏

#### Scenario: 桌面 Zen 默认展示任务状态窄栏

- **WHEN** 用户在 ≥768px 视口进入 Zen
- **THEN** 全局侧栏隐藏，专用任务状态窄栏默认展示任务状态点与当前任务标识，不展示品牌、全局导航或侧栏底栏

#### Scenario: 隐藏并恢复任务状态窄栏

- **WHEN** 用户在桌面 Zen 中点击窄栏底部的隐藏按钮，随后点击保留的展开入口
- **THEN** 整条窄栏及边框先消失，仅保留左下小型展开按钮且工作区全宽，随后无需退出 Zen 即恢复；窄栏显隐在 TUI、Shell、Git、设置标签切换间保持

#### Scenario: 移动端不展示任务状态窄栏

- **WHEN** 用户在 ≤767px 视口进入 Zen
- **THEN** 全局侧栏和任务状态窄栏均不展示，标签栏与退出按钮保持可见

#### Scenario: 退出后恢复普通布局

- **WHEN** 用户在网页全屏中点击 `out zen`
- **THEN** 全局侧栏和任务页头按进入前的普通布局恢复，既有侧栏折叠状态与宽度不变，下一次进入 Zen 时桌面任务状态窄栏恢复默认展示

### Requirement: 网页全屏的标签与快捷键行为

当前标签为 TUI、Shell 或 Git 时，系统 SHALL 支持通过 `palette-config` 中配置的工作台全屏热键切换网页全屏，包括焦点位于终端或当前工作区控件时。该热键的默认 wire 值为 `mod+shift+f`，默认 UI 展示为 `⌘⇧F / Ctrl+Shift+F`；保存成功后的自定义热键 MUST 在当前应用实例运行时生效。全屏期间用户 MUST 能在 TUI、Shell、Git 之间切换并保持全屏；无论通过何种工作台标签切换路径进入“设置”，系统 MUST 保持 Zen、任务轨显隐及固定 `out zen` 入口。普通布局的当前标签为“设置”时，全屏热键 MUST NOT 进入全屏；已经进入 Zen 的设置标签中，热键也不消费或切换状态。全屏功能 MUST NOT 截获裸 `Esc` 或将其作为退出信号，`Esc` 的既有终端、菜单、弹窗及其他应用行为保持不变。

#### Scenario: 默认热键切换全屏

- **WHEN** 当前标签为 TUI、Shell 或 Git 且使用默认配置，用户按 `Cmd+Shift+F`（macOS）或 `Ctrl+Shift+F`（Windows/Linux）
- **THEN** 系统在网页全屏与普通布局之间切换，并阻止本次已处理热键触发其他页面级重复操作

#### Scenario: 自定义热键运行时生效

- **WHEN** 用户在全局设置页将工作台全屏热键修改为另一合法热键并保存成功
- **THEN** 当前应用实例使用新热键切换网页全屏，旧热键不再触发全屏切换

#### Scenario: 合资格标签之间切换

- **WHEN** 网页全屏期间用户在 TUI、任一 Shell 与 Git 标签之间切换
- **THEN** 新激活的工作区保持网页全屏，标签栏和退出入口持续可见

#### Scenario: 进入设置保持 Zen

- **WHEN** 网页全屏期间当前标签通过点击或其他工作台标签切换路径变为“设置”
- **THEN** 系统保持全局侧栏和任务页头隐藏、任务轨显隐及固定 `out zen` 入口，展示设置内容

#### Scenario: 普通设置页不进入全屏

- **WHEN** 普通布局的当前标签为“设置”，用户按配置的工作台全屏热键
- **THEN** 系统保持普通布局，不进入网页全屏

#### Scenario: Esc 不退出全屏

- **WHEN** 网页全屏期间用户按裸 `Esc`
- **THEN** 全屏状态不因该按键改变，按键继续遵循当前终端或界面元素的既有行为

### Requirement: 网页全屏状态生命周期与工作内容保持

网页全屏开关状态 SHALL 仅属于当前任务工作台的当前会话，MUST NOT 写入 localStorage、sessionStorage、后端配置或其他持久化存储；独立的工作台全屏热键偏好按 `palette-config` 持久化，不受此限制。切换任务、离开任务工作台或刷新页面后 MUST 以普通布局进入后续页面。进入、保持及退出全屏 MUST NOT 重载页面、重建终端会话、重连终端 WebSocket、清空终端 scrollback 或丢失 Git 面板既有工作内容；非活动 TUI、Shell 和已访问 Git 工作区 MUST 继续保持既有常驻语义。进入和退出后，当前终端及 Git 工作区 MUST 随可用空间变化自动调整尺寸，无需用户刷新或重新连接。

#### Scenario: 切换任务不继承全屏

- **WHEN** 用户在某任务的网页全屏中通过任务状态窄栏或其他任务导航入口切换到另一任务
- **THEN** 新任务工作台以普通布局展示，前一任务的全屏及窄栏显隐状态均不被继承

#### Scenario: 离页与刷新恢复普通布局

- **WHEN** 用户从网页全屏离开任务工作台，或刷新当前页面
- **THEN** 后续页面以普通布局展示，且不存在可恢复的全屏持久化状态

#### Scenario: 全屏切换保持终端工作状态

- **WHEN** 用户进入再退出网页全屏
- **THEN** 既有 TUI 和 Shell 会话、WebSocket 连接及 scrollback 保持连续，当前终端自动适配新的可用尺寸

#### Scenario: 全屏切换保持 Git 工作状态

- **WHEN** 用户已访问 Git 标签并进入再退出网页全屏
- **THEN** Git 面板既有工作内容保持，当前 Git 工作区自动适配新的可用尺寸，无需刷新或重新打开面板

## MODIFIED Requirements

### Requirement: 全局应用壳层与侧栏导航

系统 SHALL 提供全局应用壳层包裹全部管理页面：左侧导航脊柱包含品牌区、指挥中心顶层项、按项目分组的任务组（任务项带 agent 状态点与注意力标记）、管理组（项目管理、设置）与底栏（⌘K 入口、本地地址、主题切换）。壳层 MUST 支持 ⌘B 快捷键与底栏按钮折叠为 44px 图标轨，折叠状态 MUST 持久化于 localStorage 并在下次打开时恢复。未认证时 MUST NOT 渲染壳层（仅呈现令牌门）。ServerStatusBanner MUST 在壳层内所有页面可见。

侧栏任务组数据 MUST 来自 App 层共享 projects store（`/api/v1/projects/stream` SSE 订阅 + 常驻低频兜底轮询，见 projects-stream spec）：壳层侧栏、指挥中心与项目管理页消费同一数据源，应用内 MUST NOT 存在第二个 `/projects` 轮询或第二条 projects 流订阅（兜底轮询属于 store 内部、single-flight 语义保持）。store MUST 暴露 `refresh()`（trailing 语义）：任何变更操作成功后调用；若调用时已有加载在途，MUST 在该请求结束后再补发一次——`refresh()` 承诺其结果反映调用之后的最新状态（MUST NOT 以 mutation 前的在途快照交差）。流订阅或兜底轮询失败时侧栏 MUST 保留上次成功数据静默展示（错误由 ServerStatusBanner 与页面级错误提示承担，侧栏本身不闪空态）。

**移动端任务入口**：≤767px 视口侧栏任务组隐藏时，普通布局的任务切换入口 MUST 由工作台页头的任务切换器承担（执行与侧栏相同的 hash 导航 + 按 taskID 重挂载），普通布局下移动端 MUST NOT 失去任务间直达能力。任务工作台网页全屏期间，任务切换入口 SHALL 随全局侧栏和任务页头暂时隐藏，此期间上述任务入口常驻要求不适用；全屏退出按钮 MUST 始终可见，退出后任务切换能力 MUST 立即恢复。网页全屏 MUST NOT 永久移除或禁用移动端任务导航。

**折叠任务悬浮详情**：全局折叠侧栏与 Zen 任务状态窄栏中的任务项 SHALL 使用自定义悬浮详情替代原生 `title` 提示。鼠标 hover 到任务状态点时 MUST 无额外人为延迟地展示任务名称、所属项目、当前状态及待处理数量（无待处理项时显示 0），移出任务项及其悬浮详情后 MUST 隐藏。两处入口 MUST 使用同一任务数据与状态文案，MUST NOT 因悬浮详情新增数据请求；全局展开侧栏及移动端的既有任务展示不受此要求影响。

#### Scenario: 跨页面导航

- **WHEN** 用户在任意页面点击侧栏的指挥中心/项目管理/设置
- **THEN** 应用切换到对应页面且侧栏保持渲染（不整页重载）

#### Scenario: 折叠持久化

- **WHEN** 用户按 ⌘B 折叠侧栏后刷新页面
- **THEN** 侧栏保持折叠的图标轨形态

#### Scenario: 侧栏任务组状态呈现

- **WHEN** 存在活跃或挂起任务
- **THEN** 侧栏按项目分组展示这些任务，活跃任务显示 agent 状态点（idle/busy/retry），有待处理注意力项的任务显示注意力标记；归档任务 MUST NOT 出现在侧栏

#### Scenario: projects 数据流驱动更新

- **WHEN** store 订阅存续期间收到 projects 流的 `snapshot` 或 `update` 帧
- **THEN** store 以帧内裸数组整表替换快照，侧栏任务组随之收敛，期间不存在对 `/api/v1/projects` 的固定 5 秒轮询请求

#### Scenario: 侧栏切换任务

- **WHEN** 用户点击侧栏任务组中的某任务
- **THEN** 应用导航至该任务工作台 `#/task/:id`

#### Scenario: 折叠任务详情无延迟展示

- **WHEN** 用户在全局折叠侧栏或 Zen 任务状态窄栏中 hover 任一任务状态点
- **THEN** 自定义悬浮详情无额外人为延迟地展示任务名称、所属项目、当前状态及待处理数量，移出任务项及详情后隐藏，且不发起额外数据请求

#### Scenario: 移动端网页全屏暂时隐藏任务入口

- **WHEN** 用户在 ≤767px 视口进入任务工作台网页全屏
- **THEN** 全局侧栏及页头任务切换器暂时隐藏，全屏退出按钮始终可见；退出后页头任务切换器及任务间直达能力立即恢复
