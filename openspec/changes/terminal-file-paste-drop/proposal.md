# Proposal: terminal-file-paste-drop

## Why

远程模式下（server 跑在 Linux 远端，浏览器在本地）用户无法把文件/图片粘贴进 TUI，也不支持把文件/图片拖入终端。根因是浏览器侧的文件内容从未被传输到 server 所在机器：ocdeck 目前没有任何文件粘贴事件处理、拖拽处理、文件上传通道与附件存储，而 opencode TUI 的原生附件能力依赖其所在机器的文件系统/剪贴板。这导致远程场景下"给 AI 看截图/文件"这一核心交互完全不可用。当前不存在按 localhost/remote 区分的文件粘贴逻辑；本地可用的现象与 opencode 对其所在机器文件系统/剪贴板的依赖相符，并不代表 ocdeck 已具备浏览器文件上传能力。

## What Changes

- Web 端终端区域新增对**粘贴文件/图片**的捕获与上传（不影响现有纯文本粘贴行为）。
- Web 端终端区域新增对**拖入文件/图片**的捕获与上传（含拖拽视觉反馈），与粘贴共用同一条上传通道；混合拖入（文件+目录）时目录分项拒绝并提示，普通文件继续处理，不遍历目录。文件选择器无常驻入口按钮，仅用于失败/未知项的重试重选。
- 上传/投递入口仅挂在 **opencode TUI 终端**；普通 shell 终端不提供入口，server 侧收到 shell 连接的投递请求也一律拒绝。
- Server 端新增**文件上传能力**：接收浏览器上传的文件并写入按任务归属的受管存储。上传请求绑定 server 签发的 WS 连接 ID（connId），仅接受任务当前 TUI 连接的上传。
- Server 端新增**投递能力**：把已上传文件交付给对应任务的 opencode TUI 终端，以其原生附件行为消费（图片与 PDF 会成为真正的附件，具体类型见附件能力表；其它类型按 opencode 原生规则处理）。投递回执分三态：已发送到终端 / 明确失败 / 结果未知；结果不确定时**不自动补发**，用户可手动重试并得到可能重复的提示。
- 新增**临时文件管理配置与生命周期**：上传目录、大小上限可配置；保留期 TTL 可配置且**默认关闭**；task 删除触发该任务上传目录的失效与回收，另有周期清理兜底停滞半成品与孤儿文件。
- 上传复用现有 Bearer 鉴权与 Origin 白名单校验（与 WS 终端同一白名单语义，校验顺序 Bearer → Origin → 任务/connId 准入）；远程部署（非 localhost Origin）下同样可用。
- 实施前先完成一次**端到端链路验证（spike）**：目标 Linux 环境上单张 PNG 图片从浏览器粘贴到 TUI 出现附件占位符。

## Capabilities

### New Capabilities

- `terminal-file-delivery`: 浏览器文件/图片经上传通道进入 server 受管存储、并投递到任务终端被 opencode TUI 消费的完整能力，包括上传约束（大小/数量）、附件能力表、安全与隔离、连接归属（connId）校验、临时文件生命周期、投递状态机与失败语义、粘贴/拖拽常态入口与重试重选（文件选择器）的行为。

### Modified Capabilities

- `terminal-streaming`: 终端 WS 协议新增附件投递控制帧（deliver/deliver_result）与 auth_ok 连接 ID 字段及能力协商要求；锁定态等既有输入门禁对投递同样生效。

## Impact

- **代码**：
  - `web/src/terminal/`（TerminalView、session 等）：新增粘贴/拖拽捕获与上传、投递状态 UI。
  - `internal/api/`：新增上传 HTTP 路由与 handler、WS 投递控制帧处理与显式类型分发。
  - `internal/config/config.go`：新增上传/临时文件管理相关配置项。
  - 新增 `internal/infrastructure/uploads` 存储组件与 application 层编排（上传/投递准入、生命周期协调）。
- **协议/API**：新增一个上传 HTTP 端点；终端 WS 协议新增控制消息类型与 auth_ok 新字段（需与旧版本 server/前端的能力协商，避免协议不兼容时产生异常行为）。
- **依赖**：无新增外部服务；存储使用 server 本地文件系统。
- **部署/运维**：新增上传目录配置与磁盘占用管理（大小上限、可选保留 TTL、task 删除回收与周期清理）；远程部署需继续正确配置 Origin 白名单（上传接口与 WS 共用同一白名单语义）。

## 范围边界与非目标

- **附件语义以 opencode TUI 原生行为为准**：图片与 PDF 会成为真正的附件（具体类型见附件能力表，唯一定义于 `terminal-file-delivery` spec）；SVG 以文本内联；其它类型文件（含无扩展名）仅作为路径文本进入 prompt，不承诺"任意文件皆附件"。
- **入口范围**：首版仅 opencode TUI 终端支持上传/投递；普通 shell 终端不支持（server 侧 shell 连接收到投递帧也拒绝）。
- **非目标**：不改变文本粘贴现有行为；不实现 OSC52 之外的终端→浏览器剪贴板新能力；首版不支持拖入目录（目录分项拒绝，不遍历）；不实现上传进度断点续传；**不做图片压缩（无损/有损）**——opencode 侧大图本就会被自动缩放，存储已由大小上限与回收机制约束，首版不引入图片管线。
- **多文件**：支持一次粘贴/拖入/选择多个文件；多文件**完整性**为强制验收（每个文件都要在 TUI 出现对应结果），最终附件**排列顺序**不承诺。
- **兼容性**：不保证对旧版（Go 时代）opencode TUI 的附件行为差异做适配；以当前 TypeScript TUI 行为为准。项目既有已验证 opencode 区间为 [1.18.14, 1.18.26]（`internal/infrastructure/opencode/CONTRACT.md`），本变更附件链路针对 v1.18.30 的验证单独记录，扩展项目兼容区间遵循现有 SOP。
