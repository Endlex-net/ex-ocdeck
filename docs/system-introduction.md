# ocdeck 系统介绍（面向 UX 设计师）

> 本文档面向负责 UI 重设计的 UX 设计师，完整描述 ocdeck 是什么、为谁服务、有哪些页面与交互、以及重设计时必须尊重的系统约束。
> 内容基于当前代码实现（截至 2026-08），可作为设计工作的唯一事实来源。

---

## 1. 产品定位

**ocdeck 是一个个人自用的「opencode 并行任务编排台」**——为 AI 编程智能体 [opencode](https://opencode.ai) 提供多任务并行管理能力的本地 Web 控制台。

- 它以**单个 Go 进程**运行在用户自己的机器上（当前仅支持 macOS），数据存 SQLite，界面是浏览器 Web UI。
- **单用户**：一个访问令牌（Bearer token）管所有事，默认只绑定 `127.0.0.1`。没有多用户、角色、权限体系——任何拿到令牌的人拥有全部能力。
- 它解决的问题：一个开发者同时 juggling 多个 AI 编码任务时，需要为每个任务提供隔离的工作目录、独立的 AI 会话、随时挂起/恢复的生命周期管理，以及一个统一的「驾驶舱」界面。

一句话：**它是一个以终端为核心的开发者工具，"AI 会话 × N 路并行" 的调度中心。**

## 2. 目标用户与核心场景

**用户画像**：一名重度使用 AI 编程智能体的开发者（即产品作者本人），习惯同时推进多条工作线。

**典型场景**：

1. **开新任务**：在项目里点一下，系统自动切出独立 git 分支 + worktree，起一个专属 AI 会话，立即开始对话。
2. **多路并行**：同时激活多个任务（如"重构 A 模块"和"修 B 的 bug"），在任务间快速切换，随时查看哪个 agent 正在忙。
3. **挂起与恢复**：临时搁置一个任务（挂起 → 进程回收但现场保留），过几天恢复，AI 会话原样接回。
4. **收尾**：在网页上直接看 diff、提交、推送，然后归档或删除任务（自动清理分支、worktree、会话）。
5. **移动端看一眼**：在手机上通过浏览器查看 agent 进度、简单接管终端。

## 3. 核心概念（领域模型）

设计师必须先理解这 5 个核心实体及其关系：

```
Project（项目） 1───N Task（任务） 1───N Session（AI 会话）
                     │
                     ├── 1 个 Git Worktree（仅 repo 项目）
                     ├── N 个 tmux 运行时会话（serve / TUI / shell）
                     └── N 个浏览器终端标签页
```

### 3.1 Project（项目）

- 注册一个本地路径作为任务的容器，两种类型：
  - **`repo`（git 仓库）**：任务获得独立分支 + worktree 隔离，有完整 Git 面板。
  - **`dir`（纯目录）**：任务直接在目录里跑，**无文件隔离**——多个并行任务共享同一目录（界面有明确警告）。
- 项目可配置**生命周期脚本**：init 脚本（任务创建后自动执行，如装依赖）、pre-delete 脚本（删除前清理）、文件继承规则（创建时从主仓库拷贝哪些文件）。
- 项目只有在没有任务时才能删除。

### 3.2 Task（任务）——核心工作单元

一个任务 = 一个分支 + 一个工作目录 + 一组 AI 会话。

**任务状态机（UX 一等公民，重设计必须完整呈现）**：

```
用户可见状态：  suspended（挂起）⇄ active（活跃）→ suspended
              suspended ⇄ archived（归档）
内部过渡状态：  creating / activating / suspending / deleting
失败状态：      creation_failed / deletion_failed（可重试、可强制删除）
```

- 合法流转：挂起→激活、激活→挂起、挂起⇄归档；删除只允许从挂起/归档/失败态发起。重试操作幂等。
- 每个任务还有 **init_status**（`none/pending/running/succeeded/failed`）：init 脚本未完成时**禁止激活和删除**；失败时提供「查看日志」「重跑 init」入口。
- 任务还可能携带 `last_error`（错误条）和 `notice`（如"有残留进程待清理"提示）。

### 3.3 Session（AI 会话）

- 每个任务**锚定唯一一个顶层 opencode 会话**：首次激活时创建，之后每次激活用会话 ID 精确恢复——用户看到的 AI 对话永远连续。
- 会话有实时运行状态：**idle（空闲）/ busy（工作中）/ retry（重试中）**，UI 上以脉冲圆点呈现。

### 3.4 Worktree（工作树）

- repo 任务的隔离检出目录，**永远在 ocdeck 自己的数据目录下**（`<dataDir>/worktrees/...`），绝不污染用户的原始仓库。
- dir 任务没有 worktree，直接用项目路径。

### 3.5 终端（Terminal）

每个任务的工作台里有两种终端标签页：

- **TUI 终端**：opencode 智能体的原生终端界面（聊天、审批、进度都在这里面），通过 xterm.js + WebSocket 流式传输到浏览器。**这是用户与 AI 交互的唯一窗口**——Web UI 本身没有聊天面板。
- **Shell 终端**：普通 shell，可随意增删，用于手动执行命令。

所有任务进程托管在专用 tmux server 里：浏览器断开**不会**杀死任何进程，重连后画面原样恢复；服务重启后活跃任务也能自动接回。

### 3.6 环境变量（三层叠加）

全局 → 项目 → 任务，逐层覆盖。**改动不是热生效**：需要挂起再激活才应用（API 会返回 `restartRequired` 提示，界面有重启提示文案）。全局变量支持 `follow_host`（跟随宿主机）/ `manual` 两种模式。

### 3.7 AI 配置

全局 AI provider 配置（openai / anthropic，key + 模型 + 思考强度），目前用于任务的**智能分支命名**（任务名 → 英文分支 slug）；未配置时退化为机械 slug，AI 故障永不阻塞主流程。

## 4. 信息架构（现状）

技术栈：React 18 + TS + Vite，无 UI 组件库、无 CSS 框架，自写 hash 路由，单一全局样式表（约 1700 行），全中文界面，纯暗色主题。

### 4.1 页面清单

| 页面 | 路由 | 角色 |
|---|---|---|
| 项目列表 ProjectsPage | `#/` | 注册/删除项目，总览各项目任务量 |
| 项目详情 ProjectDetailPage | `#/project/:id` | 项目中枢：建任务、任务列表、项目环境变量、生命周期配置 |
| **任务工作台 TaskWorkbenchPage** | `#/task/:id` | **核心工作区**：嵌入式 AI 终端 + shell 终端 + Git 面板 + 任务设置 |
| 活跃会话 ActiveSessionsPage | `#/active` | 跨项目"现在什么在跑"总览 |
| 全局配置 ConfigsPage | `#/configs` | 终端外观、全局环境变量、opencode 配置文件编辑 |
| AI 配置 AIConfigPage | `#/ai-config` | AI provider 设置 |

### 4.2 导航结构（现状痛点）

- **没有侧边栏/顶栏导航轨道**。全局壳层只有一条服务器状态横幅 + 内容区。
- 页面间靠「← 返回」按钮、整行点击下钻、页头交叉链接连接。无面包屑。
- 全局访问入口：令牌门（TokenGate）——任何 401 都会把用户弹回令牌输入页。

### 4.3 各页面详情

#### 项目列表 `#/`
- 创建表单：项目类型（git 仓库/纯目录）+ 名称 + 绝对路径；类型切换时有上下文提示。
- 项目行：名称 + 类型标记、路径、任务总数 + 分状态计数、默认分支、行内两步确认删除。
- 页头有「活跃会话」「全局配置」入口。

#### 项目详情 `#/project/:id`
- 创建任务：任务名 + **基准分支选择器**（可搜索 combobox，支持"刷新远端分支"）。
- dir 项目有"多任务共享目录"警告条。
- 可折叠区块：项目环境变量、生命周期配置。
- 任务行：名称 + ⚠错误/ⓘ提示标记、分支或路径、状态徽章、init 徽章、"日志"按钮（init 失败时）、agent 状态徽章、操作按钮组、删除。
- 创建任务成功后**自动跳转进工作台**。

#### 任务工作台 `#/task/:id`（产品的中心，100% 高度零滚动布局）
- **页头**：返回（来源感知：从活跃会话进来就返回活跃会话）、标题、分支、状态/init/agent 徽章、操作组、删除。窄屏时操作图标化 + `⋯` 溢出菜单。
- **告警条区**：last_error（删除失败时带"查看 pre-delete 日志"）、init 失败条（查看日志 + 重跑）、任务提示（最多 3 条）。
- **标签条**：`TUI` | `shell 1..n`（可关闭、`+` 新增）| 分隔符 | `Git`（仅 repo）| `设置`。所有面板保持挂载仅隐藏（保住终端和 Git 选择状态）。
- **TUI 面板**：任务活跃时是终端；非活跃时是遮罩层——过渡态 spinner、挂起态显示「激活任务」按钮、init 未完成时显示阻止原因。
- **Git 面板**：两栏 git 工作台——文件分组（已暂存/未暂存/未跟踪）+ 勾选、diff 查看（diff2html 渲染）、提交信息 + 提交、推送。**刻意不轮询**（避免打断用户勾选和阅读 diff）。
- **设置面板**：任务级环境变量 + init/pre-delete 日志查看。

#### 活跃会话 `#/active`
- 跨项目活跃任务列表：任务名、`项目 · 分支`、相对时间（刚刚/N 分钟前）、agent 状态。点击进工作台。

#### 全局配置 `#/configs`
- 终端外观（字体、字号，存 localStorage，实时生效）。
- 全局环境变量（含 follow_host/manual 模式切换）。
- opencode 配置文件编辑器：左文件列表 + 右文本编辑，**乐观锁保存**——409 冲突时弹"覆盖保存/放弃重载"对话框；保存后提示"影响 N 个活跃任务，需重启生效"。

#### AI 配置 `#/ai-config`
- provider / API Key（掩码、留空=保留原 key、永不回显明文）/ base URL / 模型 / 思考强度。保存即时生效。配置文件损坏时有修复引导。

## 5. 关键交互机制（重设计必须保留的行为）

### 5.1 数据实时性：轮询而非推送
- 管理数据**全部走轮询**（仅终端用 WebSocket）：项目列表 5s；项目详情/工作台**自适应轮询**（任务处于过渡态或 init 进行中时收紧到 2s，否则 4-5s）；活跃会话 5s 单飞。
- 出错时保留上一份好数据，不闪空态。

### 5.2 冲突与确认（409 UX 渗透全站）
- 任务操作按钮由状态机驱动，非法操作根本不出现。
- 删除/重试遇到"worktree 有未提交改动"时弹脏确认对话框。
- 删除有普通/强制两种模式（强制只跳过会话删除和 pre-delete 脚本）。
- 配置文件编辑用乐观锁 + 冲突对话框。

### 5.3 终端连接状态机
TUI/shell 终端有完整连接状态：connecting / connected / reconnecting（指数退避自动重连）/ suspended / closed（可手动重连）/ **replaced（被另一个标签页接管，提供"接管"按钮）** / gone / auth_failed。每个状态都有对应中文文案和遮罩 UI。

### 5.4 移动端终端工程（重设计的高难度区）
- **触屏默认锁定**：粗指针设备每次连接后终端默认上锁（透明遮罩拦截输入、输出仍可见），右下角浮动 🔒/🔓 按钮切换。
- **IME 补偿**：应用层仲裁中文/日文输入法候选，宁可少发不可重复——这是 TUI 里中文输入可靠的关键。
- **触摸手势合成**：锁定态/鼠标上报模式下，竖拖 → 合成滚轮滚动，点按 → 合成鼠标事件。
- **屏幕键盘适配**：软键盘弹出时终端高度夹紧到可视区并发送 resize。
- 移动端 z 轴层级契约：终端 < 锁遮罩 < 浮动锁按钮 < 连接状态遮罩（最顶，保证重连/接管永远可点）。

### 5.5 响应式现状
- **只有工作台做了响应式**：≤1024px（平板：操作图标化、Git 面板改纵向堆叠）、≤767px（手机：页头折两行）。
- **管理类页面（项目/配置等）全部是桌面固定布局**（960px 定宽），手机上只能缩放——这是明显的重设计机会点。

## 6. 现有视觉体系（供参考，可推翻）

- 单一全局样式表 + 组件级 ad-hoc 类名，无设计系统。
- 少量 CSS 变量设计 token：深色背景（`#0b0e14`）、青色强调（`#5ccfe6`）、5 个语义色（绿/黄/红/蓝/灰）。变量使用不完整，徽章/告警里有硬编码色值。
- 视觉词汇：`.btn`（primary/danger/ghost）、`.badge` 状态徽章、`.alert-bar` 告警条、`.row-list` 行列表、`.modal`、spinner + agent 脉冲动画。
- 全等宽字体、11-14px、高密度、文本字符图标（▶ ⏸ ⟳ ⋯ ⚠ ⓘ 🔒 等）。
- 整体气质：**键盘优先、信息密集的开发者工具，终端即产品**。

## 7. 重设计必须尊重的系统约束

这些由服务端强制的安全不变量，UI 不能绕过、也不应隐藏：

1. **单用户 + 单令牌**：无登录体系可设计，只有一个令牌门。
2. **AI 交互只发生在终端里**：不要幻想把聊天搬到原生 Web 面板（那是另一个产品决策）；Web UI 的职责是编排 + 终端窗口。
3. **状态机是一等公民**：过渡态 spinner、失败态重试/强制删除、init 门禁（pending/running 禁止激活和删除）必须清晰可见。
4. **两类项目表面不同**：dir 项目无 Git 面板、无分支、无脏确认；删除对话框必须说明"只删任务记录和会话数据，绝不动目录"。
5. **改动非热生效**：环境变量与 opencode 配置的修改要挂起再激活才生效，UI 必须有"需重启任务生效"的提示位。
6. **删除是危险多步操作**：脏确认、强制模式、pre-delete 脚本、失败重试——删除流程的 UI 需要承载这些分支。
7. **终端单客户端**：同一终端同时只能一个交互客户端，第二个标签页会"接管"，需保留接管交互。
8. **明文凭据警告**：环境变量明文存储（0600），界面需保留安全提示。
9. **diff 面板不自动刷新**、GitPanel 横向滚动所有权（`.d2h-wrapper`）等工程契约，视觉改版时不能破坏。

## 8. 重设计的机会点（作者视角，供参考）

- **全局导航缺失**：没有侧边栏/顶栏，跨页面跳转依赖返回按钮和零散链接。
- **管理页面无移动端适配**：只有工作台响应式。
- **无设计系统**：token 不完整、硬编码色值散落、组件样式 ad-hoc。
- **信息密度与可读性的平衡**：当前极度密集，是否引入层级和留白是核心设计决策。
- **状态呈现可强化**：任务状态机、agent 实时状态、init 进度是产品灵魂，值得更突出的视觉语言。
- **工作台布局**：标签条 + 多面板的"驾驶舱"布局是产品价值核心，重设计应优先投入。
